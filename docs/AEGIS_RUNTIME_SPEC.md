# Aegis Runtime Spec

This spec describes the first target runtime shape for the Aegis rewrite.

## Runtime Directory

```text
.aegis/
  config/
    aegis.json
    quality-gates.json
    codex-rubric.md
    claude-code-contract.md
  blueprint/
    project-blueprint.draft.md
    project-blueprint.md
    blueprint-summary.md
    project-progress.md
  current/
    current-task.md
    status.md
    work-instruction.md
    decision-request.md
    human-handoff.md
    round-summary.md
    superpower-sources.json
    superpower-summary.md
    discipline-report.md
    planning-evidence.md
    tdd-evidence.md
    debugging-evidence.md
    verification-evidence.md
    review-evidence.md
    validation-report.md
    codex-review-prompt.md
    codex-review.jsonl
    codex-review.md
  state/
    run-state.json
  archive/
    <task-id>/
```

## Source Of Truth

`state/run-state.json` is the only machine source of truth.

It should stay small:

```json
{
  "schema_version": 1,
  "project_id": "example-project",
  "task_id": "20260602-title-suggestions-001",
  "phase": "working",
  "mode": "auto",
  "last_verdict": "task-review-pass",
  "retry_count": 0,
  "updated_at": "2026-06-02T14:20:00+08:00"
}
```

It must not contain full logs, full diffs, raw Codex output, chat transcripts, secrets, or long reports.

## Navigation Files

Navigation files are short files generated by Aegis.

`blueprint/project-progress.md` is the first file Claude Code reads when resuming context. It contains project goal, completed work, current state, next likely steps, and risk summary.

`blueprint/project-blueprint.draft.md` is the working blueprint draft. Aegis may create or preserve it, but Claude Code performs the Superpower-guided drafting work.

`blueprint/blueprint-summary.md` is a concise human-facing summary rendered from the draft before confirmation.

`current/status.md` is the current dashboard. It contains the phase, current task, last gate results, blockers, and next instruction.

`current/work-instruction.md` is the current construction order. It is generated when Aegis needs Claude Code to work.

`current/round-summary.md` is a boss-readable summary generated after each `PASS`.

These files must be concise. Detailed history belongs in `archive/`.

## Main State Phases

Suggested phases:

```text
uninitialized
blueprint-draft
blueprint-confirmation
blueprint-revision
ready-for-task
task-ready
waiting-for-construction
validating
discipline-check
codex-review
need-fix
passed
paused
blocked
hard-blocked
decision-request
human-handoff
archived
```

`paused` means Aegis stopped intentionally and can resume.

`blocked` means Aegis cannot safely continue without fixing a local issue.

`hard-blocked` means Aegis must not let Claude Code self-repair without explicit user direction.

`decision-request` means the user needs to choose between options.

`human-handoff` means Aegis stops and gives the user a handoff packet.

## Main Entrypoint

The formal user-facing command is:

```text
aegis
```

The main entrypoint reads `run-state.json`, checks the Git worktree, refreshes navigation files, and advances until it hits a stop condition.

Subcommands may exist for debug and compatibility, but ordinary users should think of Aegis as one entrypoint, not a command collection.

Aegis does not launch Claude Code. The intended host is an already-running Claude Code session. Claude Code runs `aegis`, reads the refreshed navigation files, performs the instructed construction or review handoff work, and invokes `aegis` again when ready for routing.

The Claude Code-facing contract is stored in `config/claude-code-contract.md` and can be printed with:

```text
aegis contract
```

This contract is the operational rule for what Claude Code must do when the user says "Use Aegis to start/continue."

## Blueprint Flow

Aegis owns the files and state transitions for blueprint confirmation. It does not call Superpower directly.

```text
aegis blueprint:start
aegis blueprint:summary
aegis blueprint:confirm
```

`blueprint:start` creates or preserves `blueprint/project-blueprint.draft.md`, writes navigation files, and tells Claude Code to revise the draft using Superpower discipline.

`blueprint:summary` renders `blueprint/blueprint-summary.md`, writes `current/decision-request.md`, and moves run-state to `decision-request` so Claude Code asks the human to confirm or revise.

`blueprint:confirm` promotes the draft to `blueprint/project-blueprint.md` and moves Aegis to `ready-for-task`.

## Non-Interactive Design

Aegis does not prompt in the terminal.

When user input is needed, Aegis writes `decision-request.md` and stops. Claude Code then asks the user in chat.

## Claude Code Construction Handshake

When Aegis needs code changes:

1. Aegis writes `current/work-instruction.md`.
2. Aegis sets `phase` to `waiting-for-construction`.
3. Aegis stops.
4. Claude Code reads the instruction and edits code.
5. Claude Code writes work evidence.
6. Claude Code or the user runs `aegis` again.

This keeps Aegis as the gate and Claude Code as the constructor.

## Superpower Integration

Aegis uses file references, not directory takeover.

`current/superpower-sources.json` records source paths, source kinds, and summaries.

Aegis may copy key Superpower artifacts into `archive/<task-id>/` after the round passes.

`superpower:scan` is a source availability check. It proves that the required Superpower discipline materials exist.

`discipline:check` is a current-round evidence gate. It must inspect evidence that Claude Code actually followed the required discipline in the active round. It fails before Codex review when required evidence is missing, even if `superpower:scan` passed.

The first evidence files are:

```text
current/planning-evidence.md
current/tdd-evidence.md
current/debugging-evidence.md
current/verification-evidence.md
current/review-evidence.md
```

Planning, verification, and review evidence are required for completed construction rounds. TDD evidence is required for feature-style work. Debugging evidence is required for bug-fix work.

## Gate Order

The target round order is:

```text
current-task structure check
Git scope check
Superpower Discipline Gate
local quality gates
Codex read-only review prompt generation
Codex read-only review execution
Codex result render
verdict routing
```

Local gates may fail before Codex. The final semantic construction-round verdict `PASS`, `NEED_FIX`, or `NEED_HUMAN` comes from Codex review output, not from Aegis.

Verdict routing:

```text
PASS -> archive round, write round-summary, maybe continue
NEED_FIX -> generate repair instruction, retry within limit
NEED_HUMAN -> write human-handoff and stop
```

## Git Scope Check

Aegis checks changed files before every run.

Allowed:

- Files in `current-task.md` file scope
- Aegis navigation files

Blocked:

- Code changes without a current task
- Changes outside file scope
- High-risk files without explicit task permission

High-risk examples:

- Dependency files
- CI configuration
- Security or permission files
- Build configuration
- Git metadata operations
- Release and deployment configuration

## Forbidden Actions

Forbidden actions are built into Aegis:

```text
git commit
git push
git merge
git rebase
git reset --hard
delete branch
npm publish
docker push
release
deploy
rewrite git history
```

Aegis can recommend these actions to Claude Code, but cannot execute them.
